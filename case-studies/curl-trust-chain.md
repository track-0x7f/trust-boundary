# Case Study: curl — 单一决策者模式下的信任链

**状态**: 测绘中（草案）
**日期**: 2026-06-02
**观测者**: Track-0x7F

## 为什么是 curl

curl 拥有目前开源生态中最透明的安全披露流程之一。Daniel Stenberg 是唯一的 CVE 分配者和安全公告发布者。这种"单一决策者"模式在信任链上既有优点（责任清晰、决策一致）也有结构性脆弱点。

## 信任链追踪

| 信任关系 | 担保形式 | 可验证性 |
|---------|---------|---------|
| 发现者 → Daniel | 相信他会及时响应并给予 credit | 弱：Daniel 的响应时间依赖单人的工作负荷和健康状况 |
| 维护者团队 → Daniel | 相信他会在安全修复中正确代表项目利益 | 弱：无检查制衡机制 |
| 下游发行版 → Daniel | 相信公告的 CVSS 评分和修复建议准确 | 中：公告内容可审阅，但无独立验证 |
| 用户 → curl 生态 | 相信安全公告覆盖了所有已知严重问题 | 弱：用户无法区分"没有公告"和"有未公开的问题" |

## 边界条件

1. **Daniel 不可用时**（休假/健康）：披露流程有无预案？目前看是没有文档化的继任计划。
2. **发现者与 Daniel 对严重性评估不一致时**：谁有最终裁决权？Daniel。这是一种典型的"善意假设"——当发现者不同意严重性评级时，除了接受或公开，没有正式的上诉渠道。
3. **多个发现者同时报告相似问题时**：信用分配缺乏透明规则。

## 初步观察

curl 的信任架构高度依赖 Daniel Stenberg 的技术判断力和个人诚信。这不是批评——这是一种明知且接受的设计选择。但这意味着信任链的单点故障不是技术性的，是信任结构性的。

测绘仍在进行中。下一个维度：curl 安全公告中实际出现的信任相关事件（credit 争议、严重性争议、披露时间线争议等）。
