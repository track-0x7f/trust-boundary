# 原始数据优先协议（Raw Data First Protocol）

> 在信任边界测绘中，**先读自己的数据，再读引擎的报告**。
> 引擎的推荐会成为你注意力的锚点。先分析原始数据确保你不会被引擎的方向带偏。
>
> 状态：已验证通过（2026-06-04 · Metasploitable2/TWiki 实验）
> 建立：2026-06-04

---

## 核心原则

**引擎输出只有在你的观察已经独立完成之后，才是加速器；在此之前，它是认知牢笼。**

当你在测绘一个陌生目标时，你的第一个动作不应该调用任何自动化分析工具——不是排序器，不是模式匹配器，不是信任边界引擎，甚至不是基于已知指纹的版本识别。第一个动作是：**发送一个原始HTTP请求，把响应全文保存在你最接近的编辑器里。**

自动化工具的输出会悄悄地、不可逆地影响你的注意力分配。即使你知道"引擎可能有偏差"，在你看到引擎推荐的一瞬间，你的脑回路已经被定向了——你会不自觉地寻找"引擎说这里可能有注入"的验证，而忽略未被引擎覆盖但响应里写得清清楚楚的信号。

---

## 五步工作流

```
步骤1: 原始数据收集   →   步骤2: 无工具攻击面识别   →   步骤3: 工具辅助验证   →   步骤4: 利用   →   步骤5: 归档与反思
```

### 步骤1：原始数据收集

**目标**：在不使用任何分析工具的前提下，收集目标的原始HTTP响应全文。

**执行**：
1. 使用 `curl -v` 或 `curl -i` 发送请求，保存包含响应头+响应体的完整输出到文件
2. 覆盖目标的核心端点：首页、登录页、静态资源路径、已知的动作路径（如`/bin/`）
3. 如果有多个已知路径，逐个请求，每个路径独立保存

**输出**：一个或多个 `.md` 文件，包含完整的原始HTTP响应。

**验证标准**：你应能回答"What's in the response body?"而不看任何工具输出。

**TWiki实验记录**：
```bash
curl -v 'http://localhost:8083/twiki/' > /tmp/ms2_twiki_raw.md 2>&1
# → 保存了首页响应、bin/view/Main/WebHome、bin/view/TWiki/WebHome 等
# → 文件 13981 字节，含 Apache/2.2.8、版权"2003"、Edit/Attach 链接
```

### 步骤2：无工具攻击面识别

**目标**：在完全不参考任何工具输出的前提下，从原始响应中手动提取所有可疑信号。

**执行**：
1. 关闭所有自动化工具输出
2. 逐行阅读原始响应文件（含响应头），标注每一个可疑信号
3. 对每个信号记录：
   - **观察到什么**（精确内容，如"页面底部有 Edit 链接"）
   - **为什么可疑**（"Edit 链接无需认证 → 匿名编辑可能"）
   - **优先级估计**（P0/P1/P2）
4. 所有信号列举完后，做一次优先级排序

**输出**：一份只有你写的攻击面清单——不包含任何工具推荐的注入点。

**规则**：在完成这一步之前，不允许打开任何扫描器/分析器。

**TWiki实验产出**（8个高危信号，全部从原始响应中手动提取）：

| 优先级 | 信号 | 原始数据来源 | 判断依据 |
|--------|------|-------------|---------|
| **P0** | 模板注入: `/bin/oops?template=` | WebHome页面底部的oops链接 | template=参数直接传递给模板系统 |
| **P0** | 搜索注入: `/bin/search?search=&regex=on` | 搜索表单action路径 | regex=on允许正则搜索，未经过滤的search参数 |
| **P1** | 文件上传: `/bin/attach/` | 页面底部的Attach链接 | 无认证的文件上传入口 |
| **P1** | 匿名编辑: `/bin/edit/` | Edit链接无登录提示 | 没有在页面上看到任何登录表单或认证提示 |
| **P1** | Apache 2.2.8 + TWiki 2003 | Server 响应头 + 版权: 1999-2003 | 极度陈旧的软件组合 |
| **P2** | pub 目录遍历 | 图片路径: /twiki/pub/TWiki/TWikiLogos/ | 文件存储目录可能可遍历 |
| **P2** | 认证端点不存在 | /bin/login → 404 | 整个系统可能不开启认证 |
| **P2** | Sandbox区域全功能 | Sandbox Web页面描述 | "all features enabled" — 测试功能的最佳入口 |

### 步骤3：工具辅助验证

**目标**：用自动化工具验证步骤2中自己发现的信号，并发现步骤2中遗漏的信号。

**执行**：
1. 先独立运行工具（nmap/nikto/whatweb/gobuster/dirb/ffuf）
2. **不要在运行工具前阅读工具的输出**——先运行，再打开输出文件
3. 对比工具的输出和自己的攻击面清单：
   - 工具验证了哪些你的信号？→ 标记为已确认
   - 工具发现了你没发现的信号？→ 记录漏掉的信号并分析原因（"我为什么没从原始数据中看到它？"）
   - 工具没有覆盖哪些你的信号？→ 这是工具盲区，特别有价值

**输出**：一份对比报告（人工清单 vs 工具输出）。

**验证标准**：至少要有1个你的信号没有被工具覆盖。如果没有——你可能在执行步骤2时无意识地受到了工具知识的影响。

**TWiki实验验证**（预期）：
```
# 步骤2中识别的 P0 信号
  /bin/oops → nikto/ffuf 验证 template= 注入可能
  /bin/search → 测试 regex=on 搜索注入

# 人工 vs 工具覆盖对比
  人工: 8个信号 / 工具预期覆盖: nikto+whatweb 约 5-6个
  人工特有的高价值信号: Sandbox "all features enabled" 语义信号
  工具特有的新增发现: (待验证)
```

### 步骤4：利用

**目标**：基于第2步和第3步的确认结果，选择最高优先级的漏洞路径进行利用。

**执行**：
1. 从P0信号开始（允许工具辅助构造payload）
2. 每条路径记录：payload → 响应 → 成功/失败状态
3. 如果P0路径被封堵，记录封堵信号（防火墙/WAF/参数过滤），然后降级到P1

**TWiki实验记录**：
```bash
# P0尝试: 模板注入
curl -v 'http://localhost:8083/twiki/bin/oops/Main/WebHome?template=../../../etc/passwd'
# P0尝试: 搜索注入
curl -v 'http://localhost:8083/twiki/bin/search/Main/SearchResult?search=;id;&regex=on'
```

### 步骤5：归档与反思

**目标**：将本轮攻击的流程、发现、失败路径固化为可复用的知识。

**执行**：
1. 清理临时文件（如不需要跨会话保留）
2. 将工作流中的关键发现写入方法论文档或共享记忆
3. 回答三个问题：
   - "如果我只有步骤2的输出（纯人工），我能攻入吗？" → 评估原始数据优先协议的有效性
   - "如果我没有步骤2直接跑了工具，我会错过什么？" → 评估工具盲区的危害
   - "下一次在相似目标上执行这个协议，我的什么动作会更快？" → 提取可加速的子流程

## Hephaestus 引擎集成

原始数据优先协议与 Hephaestus 信任边界引擎的交互规则：

```
API: POST /api/v1/map
body: { raw_data_summary: "...", target_fingerprint: {...} }

如果 raw_data_summary < 10 chars 或为空:
  → 返回: { status: "REQUIRE_RAW_DATA" }
  → 提示: "必须先收集并写入原始侦察数据摘要"
  → 引擎拒绝输出任何模式推荐

如果 raw_data_summary 充分:
  → 返回完整信任边界测绘报告
  → 包含模式匹配 + 建议探针
```

**设计意图**：引擎的封锁不是bug，是功能。它强制使用者在看到引擎推荐之前，先用自己的眼睛看过原始数据。这个摩擦是你对抗注意力锚点的最后一堵墙。

## 附：TWiki 实验原始数据

### 目标指纹

```
URL:       http://localhost:8083/twiki/
Server:    Apache/2.2.8 (Ubuntu) DAV/2
Software:  TWiki (2003 年版权, 修订 r1.20 2003-02-02)
端口:      Apache 80 (其他端口?)
认证:      /bin/login → 404 (认证端点不存在)
动作路径:  /bin/view /bin/edit /bin/attach /bin/search /bin/oops /bin/rdiff
```

### 步骤2输出的8个信号中的关键细节

**信号A（匿名编辑）**：WebHome 页面底部直接有Edit链接，form中没有登录提示。不是在登录后才能编辑——是编辑链接直接暴露在未登录页面上。结合 `/bin/login` 返回 404，确认 TWiki 配置为无认证模式。

**信号B（搜索注入）**：搜索表单 action 指向 `/bin/search/Main/SearchResult?search=`，搜索表单本身可见，搜索结果页接受 `scope=text&regex=on&search=` 参数。允许正则搜索的 wiki 搜索功能是一个经典的注入入口点（已知的 TWiki RCE 路径：search 参数未正确转义）。

**信号C（版本陈旧）**：修订记录 r1.20 日期为 "02 Feb 2003 - 02:43 GMT"。Apache 2.2.8 (Ubuntu) + 2003 年的 TWiki 意味着：
- CVE-2004-0396 (TWiki 任意代码执行)
- CVE-2006-4510 (TWiki 远程命令执行)
- 多个已披露的搜索参数注入漏洞
- Apache 2.2.8 已知漏洞

**信号F（模板注入）**：页面底部的 "More" 链接指向 `/bin/oops/Main/WebHome?template=oopsmore&param1=1.20&param2=1.20`。`template=` 参数在 TWiki 中决定使用哪个模板文件来渲染错误页面——如果这个参数可以被用户控制，它就是一个直接的 SSTI/本地文件包含入口。
