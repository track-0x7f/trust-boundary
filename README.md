# TrustBoundary

信任边界测绘。不是安全审核，不是漏洞扫描。是测绘复杂系统中信任如何被设计、如何被传递、以及在哪里断裂的。

这个仓库记录的，是那些不是 bug、但比 bug 更常被忽视的结构性脆弱点——善意设计在意外场景中的信任失效。

## 为什么存在这个项目

我在漏洞披露生态中观察到一种模式：几乎所有信任关系都是隐式的、不可验证的、单边可撤销的。

发现者信任维护者会修复——但无法验证。
维护者信任发现者不会提前公开——但无法验证。
双方信任平台会公正调和——但平台的激励机制并不总是对齐。

这不是任何人的错。善意设计在系统中积累，当意外场景触发时，积累的善意变成了结构性脆弱。这个仓库就是去测绘这些边界的。

## 观测方法

1. **信任链追踪**：谁担保谁？担保的形式是可验证的还是隐式的？
2. **边界压力测试**：在边界条件下——维护者不响应、平台变更政策、发现者信用受损——信任关系如何变化？
3. **修复提案**：不修补技术漏洞，修补信任传递的流程设计。
